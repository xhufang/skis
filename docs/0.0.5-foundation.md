# SKIS 0.0.5 JDBC 与方言基础

0.0.5 建立后续 `SkisExecutor` 和 `findById` 使用的连接、AST 与 SQL 渲染边界。本版本仍是开发快照，不提供
查询执行器、事务或 CRUD。

## ConnectionProvider

`ConnectionProvider` 是执行内核唯一的连接获取与归还入口。连接成功获取后，执行层必须使用 `finally` 调用
`release`。

`DataSourceConnectionProvider` 调用 `DataSource.getConnection()` 获取连接，并在 `release` 时调用
`Connection.close()`。对于连接池，`close()` 通常表示归还连接；该 Provider 不提交、不回滚，也不改变连接属性。
Spring 事务连接将由后续独立 Provider 管理，不能复用这个默认释放策略。

调用方必须在 `finally` 中释放成功获取的连接。执行器实现还必须在业务失败与释放失败同时发生时，把释放失败添加为
suppressed exception，不能覆盖原始异常。

## 基础 AST

当前 AST 只包含单表主键读取所需的最小节点：

- `TableExpression` 和 `ColumnExpression`；
- 不携带运行时值的 `ParameterSlot`；
- `ComparisonPredicate` 与 `EQUAL`；
- `SelectStatement`。

节点不可变并实现结构相等。`ParameterSlot` 只保存零基逻辑序号、Java 类型和 nullability；用户传入的值不进入 AST、
结构哈希或 SQL 文本。非 nullable 参数允许使用 primitive class token，并在构造时统一规范化为对应包装类型；
nullable 参数仍不得声明为 primitive 类型。同一逻辑序号可以在语句中重复出现，但每次出现的 Java 类型和
nullability 必须一致，否则 `SelectStatement` 在构造时拒绝该语句。

生成的 `EntityMeta` 和 `PropertyMeta` 是 AST 中的规范符号，表/列引用按这些元数据实例的身份参与相等与哈希；同一
规范元数据和别名构造出的 AST 相等，结构相似但来源不同的元数据不会错误共享查询计划。

## SQL Renderer

`SqlRenderer` 将 `StatementAst` 转换为 `RenderedSql`。`RenderedSql` 包含 JDBC SQL 模板和按占位符出现顺序排列
的参数槽：

```java
PetTable pet = PetTable.PET;
ParameterSlot<Long> id = new ParameterSlot<>(0, Long.class, false);
SelectStatement statement =
    new SelectStatement(List.of(pet.id(), pet.name()), pet, pet.id().eq(id));

RenderedSql rendered = PostgreSqlDialect.INSTANCE.renderer().render(statement);
```

PostgreSQL 输出：

```sql
SELECT "pet"."id", "pet"."pet_name" FROM "shelter"."pet" WHERE "pet"."id" = ?
```

所有 catalog、schema、表、列和别名都按独立标识符处理。标识符使用双引号，内部双引号重复转义；参数始终使用
JDBC `?`，不提供字符串拼值入口。

基础 PostgreSQL/H2 Renderer 支持 schema 限定名，但暂不输出 catalog。遇到带 catalog 的 `TableMeta` 会抛出
`SqlRenderException`，防止静默忽略或产生依赖当前连接数据库的错误 SQL。

Renderer 对标识符采用保留大小写的双引号。H2 默认会把未加引号的标识符折叠为大写，因此测试建表脚本必须使用与
元数据一致的双引号名称；共享 PostgreSQL 风格脚本时，也可以显式使用 H2 的 PostgreSQL compatibility mode 和
`DATABASE_TO_LOWER=TRUE`。方言不会擅自把元数据名称转成大写，否则显式声明的大小写和跨数据库 SQL 会发生变化。

## PostgreSQL JSON

`PostgreSqlCodecs.JSON` 以 `String` 保存 JSON/JSONB 文本，读取时使用 `ResultSet.getString()`，写入时使用
`PreparedStatement.setObject(..., Types.OTHER)`。该实现不依赖 pgJDBC 的专有类，也不在客户端重复实现 JSON
解析；语法校验和 JSON/JSONB 目标类型转换由 PostgreSQL 完成。`null` 使用 `Types.OTHER` 绑定。

## 明确不属于 0.0.5 的内容

- `SkisExecutor`、查询编译和 `findById` 执行；
- insert/update/delete；
- 事务、版本推进和回滚语义；
- Join、分页、函数及通用查询 DSL；
- 数据库自动探测和连接感知的 catalog 校验；
- 真实数据库合同测试与性能基准。

这些能力分别进入后续版本，不能绕过当前 AST、方言和连接生命周期边界另建 SQL 字符串实现。
