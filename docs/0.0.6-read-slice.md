# SKIS 0.0.6 注入式执行器与无反射读取闭环

0.0.6 将 0.0.5 已建立的元模型、SQL AST、PostgreSQL/H2 Renderer、Codec 和
`ConnectionProvider` 连接成第一条可执行的 JDBC ORM 读取链路。公开入口是线程安全的
`SkisExecutor`；业务代码不接触注册表、运行时模型、查询编译器或 JDBC Executor。

## 使用方式

`SkisExecutor` 面向构造方法注入设计。Spring 自动配置进入后也只负责创建这个 Bean，不改变业务层 API：

```java
public final class PetService {
  private final SkisExecutor skisExecutor;

  public PetService(SkisExecutor skisExecutor) {
    this.skisExecutor = skisExecutor;
  }

  public Optional<Pet> findById(long id) {
    return skisExecutor.findById(PetMeta.ENTITY, id);
  }

  public List<Pet> findByName(String name) {
    PetTable pet = PetTable.PET;
    return skisExecutor.selectFrom(pet)
        .where(pet.name().eq(name))
        .fetchList();
  }
}
```

非 Spring 环境或容器集成层可以装配执行器：

```java
SkisExecutor executor =
    SkisExecutorFactory.create(dataSource, PostgreSqlDialect.INSTANCE);
```

`SkisExecutorFactory` 是装配入口，不是每次查询创建的会话。得到的执行器、实体运行时注册表和编译计划均不可变且线程安全。

## 两条查询路径

### Fast Path

`findById(PetMeta.ENTITY, id)` 使用在执行器创建时预热的单主键计划。它不创建通用 DSL Builder，不遍历插件，不解析注解，
也不进入图查询规划器。计划明确选择实体的持久化列，并复用生成式主键 Codec 和 `PetRowDecoder`。

### 单表实体 DSL

0.0.6 的 DSL 支持完整实体选择、一个等值条件以及 `fetchOne`、`fetchList` 和 `fetch`：

```java
PetTable pet = PetTable.PET;

Optional<Pet> one = executor.selectFrom(pet)
    .where(pet.id().eq(1L))
    .fetchOne();

List<Pet> all = executor.selectFrom(pet).fetch();
```

`pet.name().eq(value)` 创建的是查询层绑定谓词。编译时才生成不携带值的 `ParameterSlot`；普通参数值不会进入 SQL AST、
`equals/hashCode`、SQL 模板或计划槽位。`eq(null)` 在具备明确的 `IS NULL` 节点之前被拒绝，防止把 SQL 三值逻辑伪装成等值比较。

## 生成式运行时模型

APT 现在为 `Pet` 生成：

- `PetMeta`：纯结构元数据；
- `PetTable`：类型安全 DSL 表和列；
- `PetRowDecoder`：按 JDBC 列下标读取；
- `PetBinder`：后续 mutation 使用的实体 Binder；
- `PetRuntimeModel`：直接关联元模型、RowDecoder 工厂和每个属性的 Codec。

聚合处理器把 `PetRuntimeModel` Provider 名称写入 `META-INF/skis/entities.idx`。运行时只读取这些确定资源，不执行全类路径扫描，
也不重新读取实体注解。Provider 的类加载和实例化只发生在执行器装配阶段；查询编译、参数绑定和逐行解码均不使用反射。
AOT 或容器可以直接向 Builder 提供已构造的不可变 `EntityRuntimeRegistry`，完全绕过动态索引加载。

生成代码 ABI 从 1 更新为 2。旧生成代码或旧索引与 0.0.6 运行时混用时会在装配阶段立即失败，而不是在首次查询时出现
`NoSuchMethodError`。

## 查询编译与计划复用

每个实体拥有固定数量的原子计划槽位：

- 一个完整实体无条件 SELECT 槽位；
- 每个持久化属性最多一个等值查询槽位。

槽位上限由实体属性数量决定，不使用无界 `ConcurrentHashMap`。所有完整实体计划还共享同一个启动期创建的生成式
RowDecoder。默认无别名查询会复用这些值无关计划；带显式别名的单次查询
直接编译而不把任意用户别名放入缓存。Fast Path 的主键槽位在 `SkisExecutor` 创建时预热，稳态调用只进行身份查找、类型检查、
JDBC 获取/绑定/读取和资源归还。

## JDBC 资源与异常语义

`JdbcExecutor` 对所有查询执行以下合同：

1. 通过 `ConnectionProvider` 获取连接；
2. 创建 PreparedStatement 并验证 Binder 消耗的参数数；
3. 参数只按一基 JDBC 下标绑定；
4. ResultSet 只由生成式 Decoder 按列下标读取；
5. ResultSet 和 PreparedStatement 使用 try-with-resources 关闭；
6. 成功获取连接后始终调用 `ConnectionProvider.release`；
7. 执行与 release 同时失败时，release 异常作为 suppressed 保留；
8. `SQLException` 转换为包含 SQLState、vendor code 和 SQL 指纹的 `QueryExecutionException`，不记录参数值。

`fetchOne` 的零行结果是 `Optional.empty()`；多行抛出 `NonUniqueResultException`。`fetchList` 返回物化结果列表。

## 0.0.6 明确限制

- 只支持单列主键 `findById`；复合主键值类型留给后续 APT 切片。
- DSL 只支持单表完整实体、零或一个等值条件。
- 暂不支持 projection、Join、分页、函数、流式读取和通用布尔组合。
- 暂不包含 insert/update/delete、事务和乐观锁执行；这些进入 0.0.7。
- 反射实体回退仍未提供，默认读取路径只接受 APT 生成的运行时模型。
