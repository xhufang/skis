# SKIS 0.0.9 投影 API 重构

0.0.9 将 0.0.8 的“生成工厂 + 用户重复列清单”改为“实体绑定声明 + 结果类型查询”。目标是让投影只声明一次：
DTO 构造器即选择形状，应用查询时不再导入生成类、调用 `*Projection.of(...)` 或保存 `Projection` 常量。

## 声明投影

用户类型通过 `entity` 明确唯一来源实体，构造器参数名默认匹配持久化属性：

```java
@SkisProjection(entity = Pet.class)
public record PetSummary(Long id, String name, BigDecimal weight) {}
```

结果属性需要不同名称时，使用 `@ProjectionProperty` 显式映射：

```java
@SkisProjection(entity = Pet.class)
public record PetLabel(@ProjectionProperty("name") String label) {}
```

APT 在编译期校验属性存在性、Java 类型和可空性，并在 `.skis` 子包生成 `ProjectionProvider`。聚合处理器把 Provider
写入确定性的 `META-INF/skis/projections.idx`；执行器装配时一次性加载为不可变 `ProjectionRegistry`，查询阶段不扫描
类路径或运行时注解。

## 查询 API

```java
List<PetSummary> summaries = skisExecutor
    .selectProjection(PET, PetSummary.class)
    .where(PET.name().eq(name))
    .fetchList();
```

表参数不能省略：它既确定 SQL 的 `FROM` 和别名，也把来源实体类型 `E` 传递给后续 DSL。`QueryColumn<E, V>.eq(...)`
返回 `QueryPredicate<E>`，因此把其他实体字段产生的条件传给 `where` 会在 Java 编译期失败。

同一实体的两个别名拥有相同泛型，Java 类型系统无法区分；SKIS 在编译查询计划前继续验证谓词中的表表达式与
`selectProjection` 传入的表完全一致，拒绝跨别名条件。

## 生成和执行模型

生成的 Provider 持有不可变投影描述：结果类型、来源 `EntityMeta`、按构造器顺序排列的 `PropertyMeta`、强类型映射令牌和
`RowDecoder` 工厂。查询时注册表按 `PetSummary.class` 取回描述，并校验它绑定的实体与 `PET.entity()` 使用同一规范元数据。
随后才把属性绑定到调用方的具体表表达式并渲染选择列。

投影计划缓存键继续使用规范实体、生成式映射令牌、属性序号和谓词结构；查询参数值不进入缓存键。投影 DTO 的构造仍通过
生成代码和 JDBC Codec 完成，不使用反射式字段赋值。

## 迁移

0.0.8：

```java
private static final Projection<Pet, PetSummary> PET_SUMMARY =
    PetSummaryProjection.of(PET.id(), PET.name(), PET.weight());

List<PetSummary> summaries = skisExecutor.select(PET_SUMMARY)
    .from(PET)
    .where(PET.name().eq(name))
    .fetchList();
```

0.0.9：

```java
@SkisProjection(entity = Pet.class)
public record PetSummary(Long id, String name, BigDecimal weight) {}

List<PetSummary> summaries = skisExecutor
    .selectProjection(PET, PetSummary.class)
    .where(PET.name().eq(name))
    .fetchList();
```

迁移时删除用户侧 `*Projection.of(...)`、`Projection<E, R>` 常量和对应生成类导入；为每个 `@SkisProjection` 补充
`entity`。如果 DTO 参数名与实体属性不同，添加 `@ProjectionProperty`。投影生成代码 ABI 更新为 2，包含投影声明的模块
必须用 0.0.9 处理器重新编译，才能生成 Provider 和投影索引。

如果构建配置显式列出了注解处理器（例如 Maven 的 `<annotationProcessors>`），还必须加入新的聚合处理器；显式列表会
关闭服务文件中的自动发现：

```xml
<annotationProcessors>
  <annotationProcessor>io.skis.processor.SkisEntityProcessor</annotationProcessor>
  <annotationProcessor>io.skis.processor.SkisEntityIndexProcessor</annotationProcessor>
  <annotationProcessor>io.skis.processor.SkisProjectionProcessor</annotationProcessor>
  <annotationProcessor>io.skis.processor.SkisProjectionIndexProcessor</annotationProcessor>
</annotationProcessors>
```

依赖处理器服务发现且未配置显式列表的项目无需添加这段配置。

## 当前边界

- 一个投影只绑定一个实体，当前仍是单表查询。
- 暂不支持 Join、聚合、表达式投影、排序、分页、Tuple、Map 或 Row。
- 可空标量仍需包装为非空投影对象，以区分 SQL `NULL` 与“没有行”。
- 同一结果类型不能注册多个实体或多套选择形状；需要不同形状时声明不同结果类型。
