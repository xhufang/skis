# 无反射写入与事务

> 本文按 `0.2.7-SNAPSHOT` 维护；文件名保留历史链接，当前公开版本仍为 `0.2.0`。

当前单实体写入与查询共用元模型和 JDBC 执行内核。应用继续只注入一个线程安全的
`SkisExecutor`；APT 生成的元模型、Codec、Binder 和版本读取器负责热路径，运行时不扫描实体注解，
也不按生成类名称反射查找 Binder。

## 基础 CRUD

首个写入切片支持 `Simple Entity`、单列主键和完整实体写入：

```java
Pet pet = new Pet(7L, "Mimi", weight, false, null, null);

executor.insert(PetTable.petTable, pet);
executor.updateById(PetTable.petTable, changedPet);
executor.deleteById(PetTable.petTable, pet.id());
```

- `insert` 只生成 `ColumnMeta.insertable=true` 的列，并要求影响一行。
- `updateById` 只更新非主键、非版本且 `updatable=true` 的列；主键只进入 `WHERE`。
- `deleteById` 始终带生成式单主键条件；影响零行返回 `0`，影响多行按执行错误处理。
- 只读实体在获取 JDBC Connection 前被拒绝。
- 普通参数只保存在执行对象中，不进入 SQL AST、结构哈希或 SQL 模板。

写入计划在 `SkisExecutor` 装配阶段由固定元模型编译。`EntityRuntimeModelProvider` 直接携带生成的
`EntityMutationBinders`，因此不通过反射寻找 `PetBinder`。当前生成模型 ABI 为 7；处理器与运行时须配套使用，装配会校验生成 ABI。

查询和写入计划分别保存在共享、线程安全的 `QueryPlanCatalog` 与 `MutationPlanCatalog` 中。事务 Session
只把这两份计划绑定到事务专用 `JdbcExecutor`，不会在每次 `beginTransaction` 时重新遍历实体或渲染 SQL。
所有 Statement AST 统一校验参数 ordinal 连续性及重复 ordinal 的类型/nullability 一致性；mutation 编译还会
逐项核对方言返回的参数槽顺序，不能只靠参数数量蒙混通过。

## 乐观版本语义

版本处理只在实体声明 `@Version` 时启用：

- `NUMERIC_INCREMENT` 支持 `Byte`、`Short`、`Integer`、`Long`、`BigInteger` 和
  `BigDecimal`。
- 插入时，调用方提供的版本值原样使用；可空 Java 属性没有提供值时初始化为对应数值类型的 `0`。
- 实体携带预期版本时，更新 SQL 使用 `SET version = version + 1`，同时追加
  `WHERE version = ?`。
- 带版本条件的更新影响零行时抛出 `OptimisticLockException`。
- 实体版本值为 `null` 时，不执行隐藏查询，而是仅推进数据库版本，不追加版本相等条件。
- 没有 `@Version` 的实体不会自动增加版本列或版本条件。

例如，携带版本的更新会编译成：

```sql
UPDATE "shelter"."pet"
SET "pet_name" = ?, "weight" = ?, "adopted" = ?, "version" = "version" + 1
WHERE "id" = ? AND "version" = ?
```

`updateById` 返回受影响行数，不修改调用方传入的普通类或 record。不可变实体如需继续更新，应使用已知的
`VersionStrategy.advance(...)` 计算下一版本或重新读取数据库实体。

## 本地 JDBC 事务

推荐使用回调入口：

```java
Pet result = executor.inTransaction(session -> {
    session.insert(PetTable.petTable, pet);
    session.updateById(PetTable.petTable, changedPet);
    session.afterCommit(() -> publishChanged(pet.id()));
    return session.findById(PetTable.petTable, pet.id()).orElseThrow();
});
```

回调正常返回后才提交。运行期异常、SQL 异常或乐观锁冲突都会回滚之前的写入；回滚路径不会运行
`afterCommit`。事务内的查询和写入共享一个 Connection，各次 JDBC 操作仍关闭自己的 Statement 和
ResultSet，但不会提前归还事务连接。`inTransaction` 回调内不要手动调用 `commit` 或 `rollback`。

需要手动边界时可以使用：

```java
try (SkisSession session = executor.beginTransaction()) {
    session.insert(PetTable.petTable, pet);
    session.commit();
}
```

未调用 `commit` 或 `rollback` 的活动 Session 在 `close` 时回滚。执行失败与回滚/连接释放同时失败时，
后续失败作为 suppressed exception 保留。提交失败的结果可能未知，SKIS 不会把它错误描述为成功回滚。

`SkisSession` 非线程安全，不得跨线程使用；事务状态通过显式 Session 传播，不使用 SKIS 全局
`ThreadLocal`。当前核心不提供嵌套事务、保存点或事务传播级别。

## Spring Framework 连接复用

`skis-spring` 提供 `SpringConnectionProvider`。它使用 Spring `DataSourceUtils` 获取和释放 Connection，
因此普通 `SkisExecutor` 操作可以加入现有的 Spring `PlatformTransactionManager` 事务。该 Provider 明确拒绝
SKIS 本地 `beginTransaction/inTransaction`，避免框架直接提交 Spring 管理的连接；Spring 应用使用
`@Transactional` 或 `TransactionTemplate` 控制边界。

## 当前范围与后续任务

- 暂不支持复合主键 mutation。
- 暂不支持 `EntityPatch`、bulk mutation、批处理、upsert、returning 和生成键读取。
- `deleteById` 只校验主键，不执行版本检查。
- 暂不支持 mutation DSL、逻辑删除、审计字段和图写入。
- 当前 CRUD、乐观锁、回滚、资源与安全诊断已通过 H2/真实 PostgreSQL 合同；生成键、批量、UPSERT/RETURNING 归 `0.2.10`。
