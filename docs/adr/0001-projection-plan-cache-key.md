# ADR-0001：投影计划缓存键与治理接口

- 状态：已被 ADR-0003 部分取代；缓存治理要求继续有效
- 日期：2026-08-25
- 影响版本：0.0.8

> 自 0.2.4-SNAPSHOT 起，ADR-0003 删除实体绑定用户投影、运行时投影注册表和旧式映射令牌入口，并以
> `ProjectionMapping<R>` 稳定映射 ID 与显式选择结构取代本 ADR 的投影身份方案。本 ADR 关于缓存有界、访问过期、
> 统计、失效、参数值不入键及显式别名暂不进入旧共享缓存的要求继续有效。

## 背景

0.0.8 引入标量和用户类型投影。同一投影结构必须跨普通参数值复用编译计划，同时不能让不同结果 Decoder 共享一个
未经验证的缓存项。显式别名由用户输入，当前不适合进入共享结构缓存。

开发指南要求默认查询计划缓存有界、可统计、可失效、可清空，并允许配置最大容量和访问过期时间。缓存键及其一致性语义
属于需要 ADR 记录的架构决策。

## 问题

最初方案直接接受一个公开传入的 `Class<?> mappingType` 作为结果映射身份。两个基础设施调用方可以为不同结果类型传入
相同 Class 和选择列形状，缓存命中后通过未检查泛型转换取回第一个 Decoder，从而产生错误结果类型。

仅有固定 4096 项容量也不足以支持运行时诊断、显式运维和未来 Actuator 集成。

## 候选方案

1. 继续使用映射器 Class，并把结果 Class 加入缓存键。实现简单，但映射身份仍完全由调用方拼装。
2. 把每个 `Projection` 对象身份加入缓存键。类型安全，但每次调用生成新对象，结构相同的计划无法共享。
3. 由 APT 生成类持有带结果泛型的静态映射令牌，以令牌身份作为缓存键的一部分。

## 决策

采用方案 3：

- 每个生成的 `*Projection` 类创建一个 `private static final Projection.Mapping<R>`。
- `Projection.generated(...)` 必须接收 `Mapping<R>`，令牌泛型与返回投影的结果类型保持一致。
- 共享键包含规范实体元数据身份、映射令牌身份、选择属性的有序重复形状以及可选等值谓词属性序号。
- 普通参数值不进入键；显式别名继续绕过共享缓存，只使用不可变查询对象私有槽位。
- 共享缓存默认最大 4096 项、访问后 30 分钟过期；装配阶段可以覆盖这两个值。
- 缓存提供 hit、miss、eviction、invalidation、size 和 maximumSize 快照，支持按实体失效和全量清空。

## 后果

- 正常泛型调用不能把同一个映射令牌绑定到不同结果类型，缓存命中不再依赖调用方选择的裸 Class。
- 同一生成映射器和选择形状仍可跨投影对象、参数值、普通执行器及事务 Session 复用。
- 缓存访问由短临界区串行化；计划编译仍在首次 miss 时发生，后续命中只更新访问顺序和计数。
- 统计是累计值，显式失效和清空不重置计数，便于诊断操作前后的变化。

## 兼容性

0.0.8 尚未发布，生成代码 ABI 在本版本内直接切换为映射令牌。手写调用 `Projection.generated(...)` 的基础设施代码需迁移；
普通用户只调用生成的 `*Projection.of(...)`，不受影响。`SkisExecutor` 新增缓存诊断和清空方法，迁移步骤记录在
`CHANGELOG.md`。

## 性能影响

缓存键使用对象身份和紧凑属性序号数组，不引入反射、注解扫描或 SQL 重解析。访问过期使用单调时钟，并利用 access-order
LRU 从最旧项开始清理，不扫描已知更新的尾部。

## 安全影响

参数值仍与 SQL 模板和缓存键分离。强类型令牌消除了公开 Class 键导致的跨结果 Decoder 类型混用，不改变
PreparedStatement 参数绑定规则。

## 回滚方案

若令牌方案出现不可接受的兼容或性能问题，可以保留公共 `Mapping<R>` API，将内部键切换为“映射器 Class + 结果 Class +
选择形状”；不得回退为只有调用方 Class 的未检查缓存键。
